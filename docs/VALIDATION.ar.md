# نتائج التحقق — دوائي، المرحلتان 1–5

التاريخ: 28 أكتوبر 2026. البيئة: Windows، Flutter 3.29.2 stable، Dart 3.7.2، Java 21.

## ما تم تشغيله

- `flutter gen-l10n`: نجح.
- `dart format`: نُفّذ على ملفات Dart المعدّلة.
- `dart analyze`: نجح، `No issues found`.
- `flutter test --concurrency=1 --reporter=expanded`: نجح، **23 اختباراً**.
- اختبارات الواجهات والتحقق من RTL/LTR، التنقل، الترجمة، تكبير النص، التفضيلات، فشل التخزين وإعادة المحاولة.
- اختبارات SQLite على `sqflite_common_ffi`: CRUD، نسخ الجدول التاريخية، pause/resume، archive، التحقق، migration من v1 إلى v3، وإنشاء سجل الجرعات وتأكيد الحالة ومنع التكرار ومنع تأكيد موعد مستقبلي.
- اختبارات مخطط الإشعارات: نافذة الأيام وحد الإشعارات، المنطقة المحلية وأيام الأسبوع، DST gap/overlap، ثبات المعرفات والإلغاء عند الإيقاف.

## بناء Android

- `flutter build apk --debug --target-platform android-arm64 --no-pub`: نجح سابقاً مع AGP 8.7.0 وGradle 8.10.2 وأنتج APK ARM64 بمستوى target API 35. نسخة الاختبار هذه مرفقة في `outputs/dawaei-debug.apk`.
- يتطلب الإصدار الجديد في Google Play استهداف API 36 منذ 31 أغسطس 2026. تم تحديث ملفات المصدر إلى compile/target 36 وAGP 8.10.1 وGradle 8.11.1، وثُبتت منصة Android 36.
- لم يكتمل بناء إعداد API 36: تعثر `:gradle:compileGroovy` داخل قيود Windows، كما تعذر حل اسم `dl.google.com` لتنزيل AGP 8.10.1 واعتماديات Google Maven. لا يُمثّل APK المرفق إعداد API 36؛ يلزم إتاحة Maven ثم إعادة البناء.
- أثبت البناء الحاجة إلى Kotlin Gradle Plugin 2.0.21 بسبب صيغة `compilerOptions` في `flutter_timezone 5.1.1`، وإلى تفعيل core library desugaring بسبب `flutter_local_notifications`. الإعدادان موجودان في ملفات Android.
- Windows يتعرف على هاتف Samsung S23 Ultra وواجهة Samsung ADB، لكن ADB داخل بيئة Codex يعيد `Access is denied (5)` عند فتح USB؛ `adb devices -l` لا يعرض جهازاً. لم يمكن تثبيت التطبيق على الهاتف أو اختبار تسليم الإشعارات.
- لم يُبنَ APK على target API 36 أو AAB إصدار، ولم يُضف توقيع نشر. APK الاختبار target 35. لا يثبت نجاحه جاهزية Play أو موثوقية الإشعارات على أجهزة حقيقية.

## حدود ما تثبته الاختبارات

- اختبارات الإشعارات تستخدم fake service؛ لا تختبر صلاحيات Android أو Doze أو إعادة التشغيل أو تسليم الإشعار على جهاز.
- الإشعارات تحفظ حتى 7 أيام أو 200 إشعار، أيهما أقل. يعاد ملء النافذة عند فتح التطبيق أو عودته للمقدمة أو تحديث الأدوية/إعدادات التنبيهات. مستقبل النافذة لا يتجدد إذا ظل التطبيق مغلقاً فترة أطول؛ ذلك موضح في دليل المعمارية.
- سجل الجرعات يُولّد محلياً عند فتح اليوم أو صفحة التاريخ؛ الحالات المتأخرة تبقى pending حتى نهاية اليوم المحلي ثم تصبح «لم تُؤكّد». هذه التسمية لا تثبت عدم تناول الدواء.
- APK Debug ARM64 target 35 متاح للتجربة، لكنه غير موقع بمفتاح نشر؛ أما مصدر المشروع فيستهدف API 36. يلزم إكمال بناء API 36، واختبار Android فعلي، وفحص سياسة Play والتوقيع وإنتاج AAB إصدار.
